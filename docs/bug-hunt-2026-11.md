## 三、推迟（确认是真问题，但改动风险大于收益）

| 问题 | 为什么推迟 | 触发条件 / 建议 |
|---|---|---|
| **组合包明细之和 ≠ 订单总额**：`order_items` 只有 `price`，没有权威的 `line_total`；组合包行是"先分摊总额、再反推单价"，`price × qty` 与 `line_total` 有分位差 | 修它要给 `order_items` **加列**（改 schema）+ 改渲染 + 改不变量。当前**生产上组合包数为 0**、明细≠总额的订单也是 0 → 无线上影响 | 组合包真正启用时处理：加 `line_total` 列，渲染与不变量都改用它 |
| **订单表 `shipped_at` 列类型不一致**：迁移 003 建的是 `timestamp without time zone`，而库里其它时间列都是 `timestamptz` | 新建库与存量库类型不同；改类型要动存量数据 | 容器 TZ 变更或做 SQL 侧时间比较时再处理 |
| **游客自动注册的初始密码是"手机号后 8 位"** | 改成随机密码后，**用户拿不到密码**（线上没配短信通道）→ 账号直接废掉。可用性与安全在这里直接冲突 | 需要先有短信通道（`SMS_WEBHOOK_URL`）才能推进 |
| **外键缺 ON DELETE + 孤儿数据**：游客账号有地址/赠券时 `User.destroy` 报 23503 → 清理静默失败；删订单会留下孤儿售后单 | 改外键要动存量数据 | 加 `dataInvariants` 的孤儿检查项，把问题显式化 |

## 四、下次排查的入口

- **护栏要成对**：同一个业务动作有多条路径（取消 / 批量取消 / 删除）时，逐条核对 —— 本轮的 #9 就是"取消有、删除没有"
- **同名 router 挂多处**（`/api/users` 与 `/api/auth`）时，任何按路径匹配的保护都要覆盖全部挂载点 —— 本轮的 #8
- **默认值当"意图"用**：缺省值只能在"新建"时用，"更新"时缺省值 = 覆盖别人的数据 —— 本轮的 #4
- **异步任务要复核权限**：建任务时校验过了不等于下载时不校验（角色会被降级）—— 本轮的 #7
- **失败要回滚进度**：页码、游标、序号，失败后不回滚就会"跳过"一整页 —— 本轮的 #24
